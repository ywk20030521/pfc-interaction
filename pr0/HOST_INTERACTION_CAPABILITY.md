# Agent 宿主交互能力基线（PR0）

**版本：** 0.1  
**日期：** 2026-11-25  
**状态：** 当前宿主实测，其他宿主待验证  
**意义：** V3.1 §7.3 指出"主动汇报依赖宿主" —— 本基线决定 Skill 的主动协作能做到什么程度

---

## 1. 当前宿主（WorkBuddy）实测能力

| 能力 | 实测结果 | 对 Skill 的含义 |
|---|---|---|
| 结构化提问工具 | 可用（`AskUserQuestion`，支持 1–4 个问题、每题 2–4 选项、多选、自定义输入） | Native Chat 通道可承载单选/多选/明确决策，无需先开发 Interaction MCP |
| 问题在对话中呈现 | 可用，答案回流到 Agent 上下文 | Chat 中回答的问题不要重复投递 AUQ |
| 连续自然语言对话 | 可用 | DISCUSS / EXPLAIN / ELABORATE 语义可由普通对话承载 |
| 长任务期间持续运行 | 未在本次会话实测；取决于宿主 Agent 循环是否被工具调用阻塞 | 主动汇报策略必须假设"Agent 有机会继续调用工具"这一前提，并将其作为显式条件 |
| 定时/主动推送消息 | 未确认存在宿主级定时器 | 不承诺 Agent 退出后后台主动通知；采用"检查点即汇报点"策略 |
| 会话恢复 | 未实测 | 不依赖单次会话内存保存关键决策；文档层要求关键决策可被用户复述 |
| 文件/附件传递 | 支持本地文件引用 | 用户可通过提交 `.dat`/`.py`/参数文件介入（Mode B） |

## 2. 能力分级与 Skill 降级策略

| 级别 | 宿主特征 | Skill 行为 |
|---|---|---|
| L2 完整 | 结构化提问 + 工具调用后仍可继续 + 会话恢复 | 完整主动协作：检查点提问、讨论、AUQ 异步排队 |
| L1 基础 | 结构化提问可用，但无主动推送/恢复 | 检查点汇报 + 提问，明确声明"Agent 退出后不主动通知" |
| L0 回退 | 无结构化提问工具 | 全部交互退化为普通对话文字提问，决策仍由用户自然语言表达；决策协议不变 |

**强制规则**：Skill 不绑定特定宿主工具名。结构化提问能力以"宿主提供了什么"做能力探测，探测不到就走 L0，协议语义不变（对应 V3.1 §8.1 / §3.3）。

## 3. 待验证清单

| 编号 | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| H1 | 长任务执行期间能否继续调用 MCP 并输出消息 | 提交 `execute_task` 后 `wait_seconds` 等待期间穿插 `execute_code` 与一次对用户汇报 | 任务未被打断、消息成功送达 |
| H2 | 结构化提问的选项/多选/自定义输入 | 在真实会话调用一次 AskUserQuestion | 答案正确回流 |
| H3 | 会话中断/重启后的决策恢复 | 重启会话后询问上下文 | 明确恢复或明确不恢复，不假装有记忆 |
| H4 | 宿主是否允许 Agent 在没有用户消息时主动发言 | 观察 H1 中的汇报是否由工具结果自然触发 | 若不能，转入"用户触发式汇报"并记录限制 |

## 4. 结论

当前宿主具备 L1–L2 基础（结构化提问已实测可用），满足 Skill 第一版要求。H1/H3/H4 未关闭前，主动协作策略按 L1 设计：只承诺"Agent 正在运行、可持续调用工具"的场景，不承诺后台自治。
