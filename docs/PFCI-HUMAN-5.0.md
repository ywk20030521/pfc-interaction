# PFC Interaction 5.0 — 人机协作与决策协议规范

**规范编号：** PFCI-HUMAN-5.0  
**规范级别：** 强制  
**适用对象：** Agent Native Chat、AUQ 适配、Core、科研讨论、决策和执行授权  
**关联规范：** `01_总体架构与科研工作流规范.md`、`02_科研专业模块与技术能力规范.md`、`04_提问卡片强制设计规范_V2.md`

---

## 1. 目的

本规范定义 PFC Interaction 如何与研究人员进行持续科研协作。核心目标是避免系统退化为“问几个固定问题、收集有限答案、随后停止讨论”的表单式交互。

提问只是交互的一种。完整协作还包括主动汇报、解释现象、提出假设、讨论方案、比较利弊、参数协商、接收决策、请求授权、执行反馈和结果复盘。

## 2. 人机协作原则

1. Agent 应主动主持讨论，而不是等待用户逐项填写。
2. 用户提出观点后，Agent 必须先理解并分析，再决定是否追问。
3. 复杂科学问题不得压缩成简单单选题。
4. Agent 应提出有依据的建议、替代方案、风险和反例。
5. Agent 不得为了显得主动而编造依据或无端反驳。
6. 不设固定问题数量、固定轮数或固定问卷作为阶段完成条件。
7. 用户已明确提供的信息不得重复询问，除非上下文变化导致其失效。
8. 用户可以随时改变研究目标、参数或方案；Agent 必须识别影响范围。
9. 讨论、方案确认、执行授权、工具执行和科学验证必须严格区分。
10. 用户保留科学决策权，Agent 不得把建议自动变成用户决定。

## 3. 持续科研讨论循环

```text
接收用户意图或系统观察
       │
       ▼
读取科研上下文与历史决策
       │
       ▼
识别当前讨论主题和真正待解决问题
       │
       ▼
分析事实、假设、证据、冲突和未知条件
       │
       ▼
形成解释、建议、备选方案或风险提示
       │
       ▼
与用户开放式讨论
       │
       ▼
理解反馈，更新决策与讨论状态
       │
       ▼
判断继续讨论、调用模块、请求确认或阶段总结
       │
       ▼
检查阶段完成条件并推进/回退
```

## 4. Agent 主动协作行为

Agent 应在以下情况主动发起讨论或汇报：

- 研究目标存在多种合理解释；
- 实验设计缺少关键对照或变量控制；
- 技术路线存在重要替代方案；
- 接触模型或边界条件存在适用性风险；
- 参数缺少来源、范围或标定依据；
- 仿真达到关键检查点；
- 运行指标触发异常或风险阈值；
- 数据与研究假设明显不一致；
- 分析结果可能改变研究方向；
- 发现前序决策可能影响当前结果。

主动消息应包含：观察到什么、为什么值得讨论、可能影响、建议下一步。不要只抛出“是否继续？”这类缺少上下文的问题。

## 5. 讨论质量要求

每轮科研讨论应尽可能包含以下结构中的必要部分：

1. **当前理解：** 复述用户意图或当前问题，避免曲解；
2. **专业分析：** 说明关键机理、约束或逻辑；
3. **证据与假设：** 区分已知事实和待验证推断；
4. **备选方案：** 在存在真实替代路线时给出比较；
5. **影响分析：** 说明不同选择对实验、参数、模型和结果的影响；
6. **关键分歧：** 指出尚未解决的判断；
7. **下一步：** 提出最有价值的继续讨论方向。

并非每轮都必须输出七项，但不能用没有分析的连续追问代替讨论。

## 6. 讨论深度与结束条件

Agent 不得使用“每阶段问 3 个问题”“完成 5 个选项后自动通过”等规则。

继续讨论的触发条件：
- 关键未知条件影响研究有效性；
- 备选方案尚未比较；
- 核心假设未经讨论；
- 变量存在混杂；
- 用户与 Agent 之间存在重要分歧；
- 参数或边界选择影响模型可信度；
- 当前方案无法满足阶段完成条件。

可以暂定推进的条件：
- 用户明确要求先形成初步方案；
- 缺失信息可以通过合理假设暂时处理；
- 不确定性已明确记录；
- 后续存在可执行的验证方式；
- 暂定方案不会触发未经授权的高影响操作。

阶段总结必须保留已确认事项、建议事项、未决问题、假设、风险和下一阶段前置条件。总结不代表讨论永久终止。

## 7. Native Chat 与 AUQ 双通道

### 7.1 Native Chat

承担连续、开放式、上下文丰富的科研交流，适用于：
- 研究意义和科学问题；
- 实验类型和对照策略讨论；
- 技术路线论证；
- 接触模型适用性；
- 参数标定策略；
- 异常原因讨论；
- 结果解释和研究结论。

### 7.2 AUQ

AUQ 是可选的结构化、异步交互通道，适用于：
- 已经谈清楚的明确选择；
- 参数和范围收集；
- 多项条件确认；
- 需要稍后回答的待办；
- 执行前明确审批。

AUQ 不负责科研推理，不拥有决策权，不直接触发 PFC 执行。AUQ 不可用时，Native Chat 必须仍可完成基本协作。

### 7.3 通道选择规则

- 问题尚需专业讨论：先用 Native Chat。
- 问题已足够明确，答案适合选项、数值或短文本：可用 AUQ。
- 用户暂时离开且需要保留待回答事项：在 AUQ 可用时优先使用。
- Chat 已明确回答：不得再向 AUQ 重复提问。
- AUQ 不可用：回退 Native Chat，并说明异步队列不可用。
- 不能为了使用卡片而将复杂科研判断拆成失真的选择题。

### 7.4 双通道去重协议

每个待决事项必须有稳定事项键，建议：
`research_task_id + stage_id + decision_topic`。

提问前依次检查：
1. 当前 Chat 是否已提出该事项；
2. 是否已获得用户回答；
3. 是否存在待回答 AUQ 实例；
4. 是否需要切换通道；
5. 切换前先关闭或撤销原有效交互；
6. 更新事项当前通道和状态。

同一事项只能有一个有效交互实例。通道超时不等于用户拒绝；会话断开不等于事项失效。

## 8. 决策状态协议

建议决策状态：

- `PROPOSED`：Agent 提出建议；
- `DISCUSSING`：正在讨论；
- `CONFIRMED`：用户确认；
- `REJECTED`：用户否决；
- `DEFERRED`：暂缓；
- `SUPERSEDED`：被新决策替代；
- `INVALIDATED`：条件变化导致失效。

决策记录至少包括：
- `decision_id`
- `research_task_id`
- `stage_id`
- `topic`
- `proposal`
- `alternatives`
- `rationale`
- `user_response`
- `status`
- `evidence`
- `affected_assets`
- `supersedes`

Agent 建议不得自动进入 `CONFIRMED`。

## 9. 讨论、确认、授权、执行、验证的严格区分

| 行为 | 含义 | 是否允许自动触发下一步 |
|---|---|---|
| 讨论 | 分析科研问题 | 不产生执行授权 |
| 方案确认 | 用户确认科研方案/参数 | 不自动等于执行授权 |
| 执行授权 | 用户明确允许具体操作 | 仅限授权范围 |
| 实际执行 | 工具真实执行 | 必须取得工具证据 |
| 科学验证 | 检查模型/数据/结果是否可信 | 不得由执行成功替代 |

授权必须绑定具体任务、模型/参数版本、操作对象和影响范围。关键参数、模型或工况发生变化时，旧授权必须重新评估。

## 10. 高影响操作授权

需要明确授权的操作包括：
- 启动正式或大规模仿真；
- 覆盖已有模型、参数或结果；
- 重置、删除或清理模型状态；
- 批量执行大量工况；
- 修改已确认关键参数并重算；
- 中断正在运行的重要任务；
- 执行不可逆或可能造成数据丢失的操作。

授权记录必须说明操作内容、影响对象、版本、风险和用户确认结果。不能用“继续”“好的”等缺乏明确对象的回答推断用户批准了未说明的操作。

## 11. 异常提醒与刹车协议

### 11.1 分工

- M4：发现任务状态异常、执行停止/暂停、保存运行证据。
- M5：诊断异常原因、可信度和修正建议。
- Core：组织用户讨论、判断授权和协调下一步。
- M3：在确认后修改模型或参数。
- M6：复核数据、指标和结果变化。

### 11.2 异常等级

| 等级 | 定义 | 处理 |
|---|---|---|
| L0 信息 | 正常状态或普通提示 | 记录 |
| L1 警告 | 指标偏离但未达到停止条件 | 提示并继续监测 |
| L2 需判断 | 可能影响结果可信度 | 检查点暂停或请求判断 |
| L3 严重 | 违反停止条件、计算失控或关键数据损坏 | 按预设规则立即停止并保留证据 |

阈值必须按实验类别和物理意义配置，不得使用单一阈值覆盖所有实验。

### 11.3 诊断表达

必须分别标注：
- 已确认原因；
- 可能原因；
- 待验证假设；
- 证据来源；
- 可信程度；
- 建议动作；
- 复核条件。

## 12. 交互卡片调用约束

只有当问题已经足够明确、结构化呈现确实能降低用户负担时，才调用卡片。

卡片不得替代：
- 复杂科研讨论；
- 需要解释依据的方案比较；
- 未澄清的科学问题；
- 对用户观点的专业分析。

卡片结构、视觉和内容限制以规范 04 为唯一详细依据。规范 03 只定义何时使用、卡片回答如何进入统一决策流程。

## 13. 统一交互事件

```yaml
interaction:
  interaction_id: unique_id
  research_task_id: ""
  stage_id: ""
  decision_topic: ""
  channel: native_chat
  status: pending
  prompt_purpose: ""
  context_refs: []
  options: []
  user_response: null
  decision_id: null
  authorization_scope: null
  created_at: ""
  expires_at: null
```

交互状态和决策状态分离。一个问题已回答，不代表其决策已确认；决策已确认，不代表执行已授权。

## 14. 强制验收

- [ ] 用户可以通过自然语言持续讨论完整科研问题。
- [ ] Agent 能分析用户观点，而不是只追加问题。
- [ ] Agent 能提出有依据的替代方案和风险。
- [ ] 不存在固定问题数作为阶段完成条件。
- [ ] 已回答事项不会重复投递 AUQ。
- [ ] Native Chat 与 AUQ 使用统一事项和决策上下文。
- [ ] AUQ 不可用时基本协作仍可运行。
- [ ] 讨论、确认、授权、执行和验证严格分离。
- [ ] 参数或模型变更会触发授权有效性检查。
- [ ] 异常提醒包含证据、影响和建议动作。
- [ ] 用户拒绝或暂缓后，不执行被拒绝/暂缓的操作。
- [ ] 工具执行结果能够回到 Agent 并向用户解释。
