# PFC Interaction 5.0 — 总体架构与科研工作流规范

**规范编号：** PFCI-ARCH-5.0.1  
**修订重点：** 从阶段式问答升级为长期、深度、可追溯的科研协作  
**级别：** 强制规范  
**关联：** 02 科研专业模块与技术能力规范；03 深度科研讨论与人机协作协议；04 提问卡片强制设计规范 V2

## 0. 本次修订的根本变化

旧版虽然提出“持续讨论”，但没有定义讨论深度、如何开展多轮论证、如何保留研究过程、如何判断讨论真正完成。因此系统容易表现为：提出几个问题、收集几个答案、生成一个方案，然后停止。

本规范将核心协作单元从“问题/问答”改为**科研议题（Research Issue）**。一个科研议题必须允许持续展开、拆分、反驳、修正、验证和重新打开。科研阶段只是组织工作的大纲，不是限制讨论轮数的流程表。

## 1. 产品定位

PFC Interaction 是面向 PFC2D/PFC3D 数值模拟研究的轻量化科研协作 Skill。它以 Agent 为科研语义理解和协作主体，以研究人员为科学判断和关键决策主体，以六个专业模块提供专业能力，以 Itasca MCP/Bridge 和现有 Visualization Skill 提供执行及可视化能力。

它必须支持：
- 从模糊研究想法逐步形成可检验的科学问题；
- 对研究对象、机理、假设、实验设计和技术路线开展多轮讨论；
- 逐项论证实验变量、对照策略、模型选择和参数来源；
- 根据文献、实验资料、PFC 文档、模型状态和仿真数据修订方案；
- 在研究推进中持续维护问题、假设、分歧、决策和证据；
- 在异常和新结果出现时返回前序议题重新讨论；
- 形成可追溯的科研档案，而不只是最终方案文件。

## 2. 强制设计原则

1. **科研议题驱动：** 讨论围绕议题树推进，不围绕固定问卷推进。
2. **深度优先：** 重要科学问题必须经过分析、质疑、比较和修订。
3. **迭代可持续：** 每个议题可多轮讨论、暂停、重开和版本化。
4. **用户知识不可替代：** Agent 主动获取实验经验、真实条件和隐性约束，不得用通用知识覆盖用户事实。
5. **Agent 必须有实质贡献：** 每轮应提供分析、证据、反例、比较或综合，不得把追问当成主要工作。
6. **不以轮数代替质量：** 轮数是过程指标，论证完整性和证据质量才是完成标准。
7. **禁止过早收敛：** 关键假设、变量耦合、模型适用性和结果解释未审查时，不得自动完成阶段。
8. **允许暂定推进：** 可明确假设和风险后暂定推进，但必须记录复核条件。
9. **过程资产化：** 讨论结论沉淀为议题、假设、决策、参数、证据和版本记录。
10. **轻量实现：** 首选 Skill 文件、Markdown/JSON 与宿主上下文，不默认建设独立 Web、数据库或服务端。
11. **工具边界清晰：** 复用 itasca-mcp 执行能力和现有 Visualization Skill。
12. **实现状态诚实：** 规范描述目标，不代表能力已经实现。

## 3. 总体架构

```text
研究人员
  ⇅ 持续科研讨论 / 决策 / 专业经验 / 授权
Agent Native Chat ───── AUQ（可选结构化异步通道）
  ⇅
PFC Interaction Core
  ├─ Research Context：课题上下文与科研档案
  ├─ Issue Manager：议题树、问题队列、依赖关系
  ├─ Discussion Engine：多轮分析、质疑、修订、综合
  ├─ Evidence & Hypothesis Manager：证据、假设、不确定性
  ├─ Decision Manager：决策、分歧、暂定结论、失效
  ├─ Workflow Orchestrator：六阶段和模块调用
  └─ Change & Review Manager：变更影响、阶段复审、重开
  ⇅
六阶段科研工作流 + M1–M6 专业能力
  ⇅
Itasca MCP/Bridge、PFC2D/PFC3D、数据文件、Visualization Skill
```

Core 不只是路由器。它必须知道当前课题要回答什么、当前议题论证到哪里、哪些结论是用户事实/Agent 推断、哪些方案被否决及原因、哪些决策只是暂定、哪些新证据会使旧结论失效。

## 4. 科研对象模型：Research Issue

一个课题包含多个阶段；一个阶段包含多个议题；议题可以拆分为子议题；一个议题可关联多个假设、方案、证据和决策。

议题类型：
`SCIENTIFIC_QUESTION`、`MECHANISM`、`HYPOTHESIS`、`EXPERIMENT_DESIGN`、`CONTROL_AND_COMPARISON`、`MODEL_SELECTION`、`BOUNDARY_CONDITION`、`PARAMETER`、`CALIBRATION`、`MEASUREMENT`、`NUMERICAL_RISK`、`ANOMALY`、`DATA_QUALITY`、`INTERPRETATION`、`LIMITATION`、`NEXT_STUDY`。

议题状态：
`OPEN`、`UNDER_DISCUSSION`、`NEEDS_EVIDENCE`、`NEEDS_USER_INPUT`、`PROVISIONAL`、`DECIDED`、`VALIDATED`、`REJECTED`、`DEFERRED`、`REOPENED`、`SUPERSEDED`。

`DECIDED` 表示形成决策，不等于已验证；`VALIDATED` 必须有证据；`PROVISIONAL` 必须记录假设、风险和复核条件；`DEFERRED` 不能当作已解决；重开必须保留历史版本。

## 5. 六阶段科研工作流

六阶段是科研工作地图，不是一次性闯关流程。每阶段可能反复进入，多个阶段也可并行讨论。

### S1 研究对象、背景与科学问题

讨论：研究对象的物理实体、尺度、材料和场景；工程背景与科学背景；研究意义和理论问题；已知现象、已有研究和知识缺口；可检验科学问题；研究假设、竞争性解释和反例；研究边界；PFC 方法适用性、尺度效应和简化假设；结果如何支持或否定假设。

不能只提取“研究对象、目的、变量”就结束。必须把问题转化为可检验命题，并讨论至少一种可能的反向解释。

产物：研究简报、科学问题树、假设登记表、研究边界、资料缺口清单、研究路线候选版本。

### S2 实验类别、对照与变量设计

讨论：实验类别选择理由；是否需要基准组/对照组/验证组；自变量、因变量、控制变量、干扰变量；变量耦合；单因素与多因素方案；工况数量、重复性、随机性和代表性；观测量能否区分竞争机理；无法独立控制的变量；成本和信息增益。

对照组不是形式要求。必须论证为什么需要/不需要，并说明比较能排除什么解释、不能排除什么解释。

产物：实验设计论证、变量关系图、对照策略、工况矩阵、观测指标和采集计划、设计风险清单。

### S3 技术方案与 PFC 建模路线

讨论：PFC2D/PFC3D 选择；试样几何、尺寸、颗粒级配和颗粒数量；接触模型候选及物理含义；细观参数与宏观响应关系；边界条件、加载方式、伺服和停止条件；初始状态和平衡策略；测量、历史变量和数据输出；模型简化影响；数值稳定性、成本和验证策略。

不能只给出可运行脚本方案。关键建模选择必须说明替代方案、适用条件和潜在失效方式。

产物：技术路线比较、模型设计、建模假设、模型检查清单、验证计划、数据采集设计。

### S4 参数确定、敏感性与标定

讨论：参数物理意义和单位；来源（实测、文献、反演、经验初值或待标定）；可识别性；参数耦合和相关性；合理范围及依据；标定目标、目标数据和误差函数；标定顺序、工况和停止准则；敏感性与不确定性；竞争解释；独立验证；参数适用范围及外推限制。

禁止将参数输入、参数优化和参数标定混为一谈。达到某一拟合误差不自动证明参数唯一或模型正确。

产物：参数登记表、来源与可信度、标定方案、敏感性计划、标定历史、误差记录、独立验证结果和适用范围说明。

### S5 仿真执行、监控与异常干预

讨论：执行前模型/参数/工况/授权版本；运行检查点与监测指标；正常阶段变化和异常信号区别；停止阈值和刹车规则；任务失败、停滞、崩溃和数据缺失；恢复、重跑、回滚或修改；修改后哪些结果失效；重算成本；异常是否可能是研究现象本身。

M4 负责运行控制，M5 负责原因诊断。自动刹车必须有明确条件和安全边界。

产物：执行计划、任务记录、检查点、异常证据、诊断报告、恢复/重跑决策和变更记录。

### S6 结果分析、解释与科研总结

讨论：数据完整性和质量；指标定义、单位和处理口径；结果是否支持或否定假设；与对照、基准数据和文献比较；差异机理；竞争性解释；数值误差、尺度效应和模型局限；统计不确定性和稳健性；结论适用范围；不能从现有数据推出的内容；补充实验需求。

产物：数据清单、分析配置、定量结果、比较报告、诊断报告、假设检验记录、结论草案和后续研究建议。

## 6. 阶段完成不是答题完成

阶段完成必须检查：
1. 核心议题已建立并有状态；
2. 关键概念、变量和假设定义清楚；
3. 关键选择有理由和备选方案比较；
4. 主要风险与限制被识别；
5. 未决事项已明确记录；
6. 关键决策由用户确认或明确标记为暂定；
7. 阶段产物可供后续使用；
8. 有明确复审触发条件。

高风险或高耦合议题不得仅因用户选择一个选项而通过阶段门槛。

## 7. 迭代与回退

S2 可因新问题返回 S1；S3 可因实验不可实现返回 S2；S4 可因参数不可辨识返回 S2/S3；S5 可因异常返回 S3/S4；S6 可因结果不支持假设返回 S1–S4。新文献、新数据或用户补充事实可重开任一议题。

重开必须记录触发证据、受影响议题和决策、模型/参数/工况版本、需重做的分析或仿真，以及不受影响的历史资产。

## 8. 科研档案与上下文连续性

最低档案：
- `PROJECT_CHARTER.md`：研究目标、边界、背景；
- `ISSUE_TREE.md`：议题树和依赖；
- `DISCUSSION_LOG.md`：关键讨论摘要和未决事项；
- `HYPOTHESIS_REGISTER.md`：假设及状态；
- `DECISION_REGISTER.md`：决策、理由、版本和失效关系；
- `ASSUMPTION_REGISTER.md`：未经验证的假设；
- `EVIDENCE_INDEX.md`：证据目录及来源；
- `EXPERIMENT_DESIGN.md` / `EXPERIMENT_MATRIX.csv`；
- `PARAMETER_REGISTER.csv`；
- `MODEL_REGISTER.md`；
- `SIMULATION_LOG.md`；
- `ANOMALY_REGISTER.md`；
- `ANALYSIS_REGISTER.md`；
- `CHANGELOG.md`。

这些是逻辑资产，不要求第一版建设数据库。优先 Markdown/JSON/CSV 文件。

## 9. 事实与证据类型

`USER_FACT`、`USER_EXPERIENCE`、`SOURCE_FACT`、`TOOL_OBSERVATION`、`COMPUTED_RESULT`、`AGENT_INFERENCE`、`AGENT_PROPOSAL`、`UNVERIFIED_ASSUMPTION`。

必须记录来源、时间/版本、适用条件和可信度。不得将用户经验改写为普遍事实，也不得把推断升级为工具观察。

## 10. 强制验收

使用真实复杂课题验收，而不是单轮问答示例。必须验证同一议题连续深入讨论、用户多次改变观点后版本管理、Agent 实质分析、子议题依赖、暂定决策重开、跨会话恢复、阶段回退、科研档案完整性和执行/验证证据。

## 11. 与其他规范的关系

模块职责和专业方法以规范 02 为准；讨论迭代、协作和决策以规范 03 为准；卡片呈现以规范 04 为准。本规范定义总体架构、阶段、资产和验收门槛。
