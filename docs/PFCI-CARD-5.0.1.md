# PFC Interaction — 提问卡片强制设计规范 V2（5.0 深度协作修订）

**规范编号：** PFCI-CARD-5.0.1  
**级别：** 强制 UI/交互规范  
**关联：** 01 总体架构与科研工作流规范；02 科研专业模块与技术能力规范；03 深度科研讨论与人机协作协议

## 1. 卡片定位

提问卡片是持续科研讨论中的结构化输入工具，不是科研讨论主体，不是问卷系统，也不是阶段推进器。

卡片只适合承载已经讨论到足够明确的事项，例如：明确选项的方案确认、参数值/范围/单位填写、多项已确定条件的结构化录入、延迟回答待办和具体执行操作授权。

如果问题仍涉及科学机理、研究意义、变量因果、模型适用性或多个竞争性解释，应继续使用 Native Chat 讨论，不能提前做成卡片。

## 2. 强制原则

1. 单卡单议题、单卡单决策；
2. 默认一次只展示一张卡片；
3. 同屏最多三项紧密相关的子问题；
4. 先讨论后结构化，卡片不代替论证；
5. 允许用户补充自由文本；
6. 选项必须有明确含义和边界；
7. 推荐项必须展示依据；
8. 默认值不等于用户确认；
9. 参数值必须有单位和来源状态；
10. 方案确认不等于执行授权；
11. 提交后必须反馈对研究方案的影响；
12. 卡片结果必须回写原议题和决策记录；
13. 不以卡片完成数量作为科研进度；
14. 视觉风格简洁、克制、科研化；
15. 窄屏、键盘和辅助交互必须可用。

## 3. 卡片类型

### 3.1 讨论收敛卡
只用于主要讨论已完成、需要把阶段性意见结构化记录的场景。不是让用户在未讨论时选方向。

必须显示：当前议题、已讨论主要观点、尚存分歧、需要用户确认的唯一事项、可补充/修正文本、暂定或暂缓选项。

### 3.2 参数登记卡
必须显示：参数名、物理意义、符号、单位、当前值、建议范围、来源类型、依据/引用、是否已标定、已知耦合提醒。

来源类型至少区分：实测、文献、经验初值、反演估计、待标定、用户指定。不得把建议值伪装成实验事实。

### 3.3 方案确认卡
用于用户确认已讨论成熟的实验/模型/分析方案。必须显示方案摘要、适用条件、替代方案未选原因、未决风险和确认影响。

### 3.4 执行授权卡
用于具体高影响操作。必须明确操作内容、对象、模型/参数/工况版本、是否覆盖/删除/重置/批量执行、预期影响和风险、授权范围、拒绝或暂缓后的行为。普通方案确认卡不得复用为执行授权卡。

### 3.5 检查点决策卡
用于仿真到达预设检查点，需要用户选择下一步。必须附真实运行状态、关键证据、当前风险和继续/暂停/停止/调整的影响。不得只显示孤立的“继续吗？”。

## 4. 内容密度与长度

| 元素 | 强制要求 |
|---|---|
| 标题 | 建议不超过 20 个汉字 |
| 摘要 | 建议不超过 50 个汉字 |
| 同屏问题 | 默认 1 个，最多 3 个相关子项 |
| 选项数量 | 原则上 2–5 个；不适用时允许自由输入 |
| 选项说明 | 每项一行优先，复杂依据折叠 |
| 单位 | 数值参数必须显式显示 |
| 来源 | 参数/证据型卡片必须标注来源状态 |
| 推荐依据 | 推荐项必须有依据；无依据不推荐 |
| 风险 | 呈现当前决策相关风险，完整分析留在对话 |

长度限制为了可读性，不得通过删掉关键科学条件满足字数。复杂内容放在 Chat 正文或可展开依据区域。

## 5. 推荐结构

```text
阶段 / 议题编号
标题：当前需要确认的具体事项
简要摘要：为什么现在需要确认

已讨论结论
- 当前共识
- 尚存分歧
- 影响范围

选项 / 参数输入
- 选项名称 + 简短含义
- 自定义补充
- 暂定/暂缓（适用时）

依据与风险（可折叠）
- 推荐理由
- 适用条件
- 主要限制

操作区
- 返回讨论
- 暂缓
- 确认方案 / 明确授权（语义严格区分）
```

## 6. 视觉设计系统

- 延续既有 Nature-style 科研视觉基调；
- 浅色背景优先，低饱和、低装饰；
- 信息层级依靠字体、留白和对齐，不依赖大面积彩色块；
- 统一字体、字号层级、间距、圆角、边框、按钮和焦点状态；
- 中性颜色表示普通信息；
- 蓝色系表示信息和常规选择；
- 橙色系表示注意事项；
- 红色系表示严重风险或不可逆操作；
- 绿色只表示真实成功/已验证状态，不表示推荐或未经验证的正确性；
- 颜色不能作为唯一状态表达；
- 关键数值、单位和参数名必须清楚对应；
- 窄屏选项纵向排列，不得横向溢出或遮挡主操作；
- 高级依据默认折叠，但不能隐藏影响决策的关键风险。

## 7. 提交与回写

卡片提交后必须：
1. 记录 `interaction_id`；
2. 关联 `research_task_id`、`issue_id`、`decision_id`；
3. 保存用户原始回答，不得只存转换后的摘要；
4. 更新议题状态；
5. 更新决策状态；
6. 检查是否需要重新讨论；
7. 检查是否需要执行授权；
8. 向用户说明回答对研究方案的影响；
9. 更新科研档案和版本记录。

提交卡片不等于科学假设已验证、模型已构建、参数已标定、PFC 已执行或执行结果成功。

## 8. 反模式

- 将复杂研究方向拆成连续十几道单选题；
- 用卡片取代机理讨论；
- 用“其他”掩盖选项设计不足；
- 没有依据却显示推荐；
- 默认勾选并诱导确认；
- 将建议值写成已标定参数；
- 将方案确认按钮当作执行授权；
- 用户提交后不解释影响；
- 重复提问已在 Chat 回答的事项；
- 为满足字数删除必要单位、风险或边界；
- 用卡片数量或完成率评价科研讨论质量。

## 9. 强制验收

- [ ] 复杂科研议题先在 Chat 讨论；
- [ ] 单卡单议题、单卡单决策；
- [ ] 默认单卡，同屏最多三项相关问题；
- [ ] 参数名称、物理意义、单位、来源状态完整；
- [ ] 推荐依据和适用条件清楚；
- [ ] 支持用户补充和暂缓；
- [ ] 方案确认与执行授权严格分开；
- [ ] 提交后回写议题、决策和科研档案；
- [ ] Agent 对提交结果给出实质反馈；
- [ ] 窄屏无溢出和遮挡；
- [ ] 卡片不直接触发 PFC 工具；
- [ ] 不以卡片数量作为阶段完成依据。

## 10. 版本继承说明

本规范继承 V2 的单卡单决策、默认单卡、最多三项相关问题、标题/摘要长度、2–5 个选项、推荐依据、高级依据折叠、Nature-style 视觉系统和窄屏适配要求。本次增加“先深度讨论、后卡片收敛”、议题关联、科研档案回写和决策/授权分离。
