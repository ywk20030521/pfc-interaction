# PFC Interaction — 提问卡片强制设计规范 V2

**规范编号：** PFCI-CARD-5.0  
**规范级别：** 强制 UI/交互规范  
**适用对象：** PFC Interaction 中所有结构化提问、参数决策、执行确认卡片  
**关联规范：** `01_总体架构与科研工作流规范.md`、`02_科研专业模块与技术能力规范.md`、`03_人机协作与决策协议规范.md`

---

## 1. 目的与定位

本规范约束 PFC Interaction 的提问卡片，使其简洁、美观、逻辑清晰、具有科研语义，并且不会把复杂科研讨论退化为大量机械选择题。

卡片是 Agent Native Chat / AUQ 协作中的结构化呈现方式，不是独立科研决策系统。卡片只负责帮助用户理解一个明确事项并表达回答；科研解释、决策归纳和后续推进仍由 Agent 与 Core 完成。

## 2. 强制设计原则

1. **单卡单决策：** 一张卡片只解决一个明确的决策主题。
2. **默认单卡：** 默认一次展示一张卡片；最多同时展示 3 个彼此相关的问题。
3. **简洁优先：** 只展示完成当前决策所必需的信息。
4. **先讨论后结构化：** 复杂科学问题必须先在 Native Chat 中讨论清楚，再将明确事项转成卡片。
5. **选项有意义：** 选项必须互斥、可理解且覆盖合理；不得为了凑数量设置无意义选项。
6. **允许表达未知：** 在适用时提供“其他”“暂不确定”“暂缓决定”或自定义输入。
7. **依据可追溯：** 推荐选项必须有依据；没有充分依据不得默认推荐。
8. **确认不等于授权：** 方案确认卡不得伪装成执行授权卡。
9. **结果有反馈：** 用户提交后，Agent 必须解释回答对科研方案和后续步骤的影响。
10. **视觉克制：** 使用统一设计系统，避免装饰性颜色、冗余边框和信息堆叠。

## 3. 卡片类型

### 3.1 科研讨论卡

用途：在已有讨论基础上，帮助用户明确研究方向、实验策略或技术路线中的一个具体选择。

要求：
- 展示当前问题和必要背景；
- 可以提供备选方向，但必须允许用户补充观点；
- 不得将复杂的机理判断强行限制为单选；
- 对有争议或证据不足的问题，优先返回 Chat 继续讨论。

### 3.2 参数决策卡

用途：收集已讨论明确的参数值、范围、单位或参数方案。

要求：
- 参数名称、物理意义、单位必须清楚；
- 显示建议范围和来源（若已知）；
- 区分用户输入、文献值、经验估计和待标定值；
- 不得把初始值标记为已标定；
- 对关键参数显示其影响范围或风险；
- 参数变更后必须更新决策和版本记录。

### 3.3 执行确认卡

用途：对具有实际影响的操作请求明确授权。

要求：
- 明确具体操作；
- 明确作用对象和模型/参数版本；
- 明确潜在影响和风险；
- 明确是否覆盖、重置、批量运行或中断；
- 用户必须作出清晰授权；
- 不能用普通参数选择卡代替；
- 授权仅对卡片明确列出的操作范围有效。

## 4. 内容长度与信息密度

以下是默认强制上限；只有确有必要且不会破坏窄屏阅读时才可例外：

| 元素 | 规范 |
|---|---|
| 卡片标题 | 不超过 20 个汉字 |
| 简要说明 | 不超过 50 个汉字 |
| 选项数量 | 原则上 2–5 个 |
| 同屏问题数 | 默认 1 个，最多 3 个相关问题 |
| 推荐说明 | 一句话说明依据 |
| 高级依据 | 默认折叠，用户需要时展开 |
| 参数单位 | 必须显式显示 |
| 风险提示 | 只展示与当前决策直接相关的风险 |

禁止将整段技术报告复制进卡片。详细背景应留在对话正文或折叠说明中。

## 5. 卡片信息结构

推荐结构：

```text
┌─────────────────────────────────────┐
│ 阶段标识 / 决策类别                  │
│                                     │
│ 决策标题（≤20字）                   │
│ 简要说明（≤50字）                   │
│                                     │
│ [必要背景 / 当前条件]               │
│                                     │
│ ○ 选项 A                            │
│   简短解释                          │
│ ○ 选项 B                            │
│   简短解释                          │
│ ○ 其他 / 自定义（适用时）           │
│                                     │
│ 推荐依据（有依据才显示）            │
│ 高级依据（默认折叠）                │
│                                     │
│ [暂缓]                 [提交选择]   │
└─────────────────────────────────────┘
```

卡片必须清楚呈现：
- 当前属于哪个科研阶段；
- 需要用户决定什么；
- 为什么现在需要决定；
- 可选项及其差异；
- 回答后会影响什么；
- 是否涉及执行授权。

## 6. 选项设计规范

- 选项应互斥；如果可多选，必须明确标注。
- 选项文字应描述真实方案，不使用模糊的“方案一/方案二”。
- 每个选项可附一行短解释。
- 默认值不能暗示用户已经确认。
- 推荐选项必须有事实、实验条件或明确推理依据。
- “其他”应允许用户补充。
- “暂不确定/暂缓”应在研究判断尚不成熟时可用。
- 不得把“我不知道”自动解释为同意默认方案。
- 数值输入必须校验单位、范围和有效性；超出建议范围时应说明，不得静默截断。

## 7. 推荐与依据呈现

推荐项只有在有明确依据时才显示。推荐说明应回答：
- 推荐什么；
- 依据是什么；
- 适用条件是什么；
- 主要局限是什么。

高级依据默认折叠，避免首屏拥挤。展开内容可包括文献依据、PFC 手册依据、前序实验数据、计算结果或 Agent 推理链摘要。不得展示未经验证的内容为权威依据。

## 8. 视觉设计系统

### 8.1 整体风格

- 延续 PFC Interaction 既有 Nature-style 科研视觉基调；
- 简洁、克制、专业；
- 强调信息层级，不依赖大面积彩色背景；
- 避免过度圆角、厚重阴影、渐变装饰和按钮堆叠；
- 卡片应融入 Agent 对话，而不是看起来像独立商业问卷。

### 8.2 字体与排版

- 使用宿主可用的统一字体体系；
- 标题、说明、选项、辅助依据有清晰层级；
- 正文保持易读行高；
- 数值、单位和参数名称对齐；
- 长技术名词允许自然换行；
- 不使用过小字体承载关键决策信息。

### 8.3 颜色语义

颜色只用于语义，不作为装饰：

- 中性：普通说明和未决事项；
- 蓝色系：信息、参数或常规决策；
- 橙色系：需要注意的风险；
- 红色系：严重风险、不可逆操作或明确停止；
- 绿色系：仅用于已验证或成功状态，不用于未经确认的推荐。

不得仅依靠颜色表达状态，必须同时提供文字标签或图标语义。

### 8.4 组件一致性

统一：
- 字体；
- 间距；
- 圆角；
- 边框；
- 选项样式；
- 按钮高度；
- 焦点状态；
- 禁用状态；
- 错误提示；
- 加载状态。

避免不同卡片类型自行创造一套视觉语言。

### 8.5 窄屏适配

- 窄屏下选项纵向排列；
- 不允许横向溢出；
- 长说明可折叠；
- 主操作按钮保持可见；
- 多卡片不得造成页面过长和操作混乱；
- 参数名称、数值和单位不能因压缩而失去对应关系。

## 9. 交互行为规范

### 9.1 提交前

- 必要字段校验；
- 清楚显示当前选择；
- 允许修改；
- 高影响操作再次显示影响范围；
- 禁止默认勾选具有授权含义的选项。

### 9.2 提交后

- 展示已提交状态；
- 将回答绑定到唯一 `interaction_id` 和 `decision_id`；
- 回写统一科研上下文；
- Agent 解释回答影响；
- 判断是否需要进一步讨论、确认或授权；
- 不得直接把回答当作 PFC 已执行。

### 9.3 取消、暂缓和超时

- 取消不等于拒绝；
- 暂缓不等于同意；
- 超时不等于用户拒绝；
- 会话断开不等于决策失效；
- 卡片过期时必须重新检查上下文和参数版本。

## 10. 卡片与交互协议的关系

卡片只承载交互展示和输入。以下内容由规范 03 负责：
- 何时提问；
- Native Chat/AUQ 如何路由；
- 如何去重；
- 回答如何形成决策；
- 何时请求执行授权；
- 何时判定决策失效。

卡片不能绕过 Agent/ Core 直接触发 PFC 工具。

## 11. 反模式（禁止）

- 一张卡片塞入多个无关科研问题；
- 把完整科研讨论变成 10 个连续单选题；
- 选项只有“是/否”却没有解释背景；
- 选项文字冗长，复制技术报告段落；
- 没有依据却标记“推荐”；
- 把默认值视觉上伪装成已确认；
- 将参数填写卡当成执行授权；
- 用颜色单独表达警告或成功；
- 窄屏出现横向滚动或按钮被遮挡；
- 用户提交后没有任何解释或反馈；
- Chat 已经问过并得到回答，又创建同一 AUQ 问题。

## 12. 强制验收清单

- [ ] 一张卡片只解决一个决策主题。
- [ ] 默认一次展示一张卡片，最多三项相关问题。
- [ ] 标题不超过 20 个汉字。
- [ ] 简要说明不超过 50 个汉字。
- [ ] 选项原则上为 2–5 个。
- [ ] 复杂科学判断先讨论后结构化。
- [ ] 推荐项有依据，无依据不推荐。
- [ ] 高级依据默认折叠。
- [ ] 参数名称、数值、单位和来源清楚。
- [ ] 科研讨论卡、参数决策卡、执行确认卡语义不同。
- [ ] 讨论、确认、授权、执行和验证状态分离。
- [ ] 颜色具有一致语义且不作为唯一状态表达。
- [ ] 字体、间距、圆角、边框和按钮统一。
- [ ] 窄屏无溢出、遮挡和错位。
- [ ] 用户提交后 Agent 给出有意义的反馈。
- [ ] 卡片无法绕过 Core 直接执行 PFC 操作。

## 13. 版本与继承声明

本 V2 规范承接此前《PFC Interaction：提问卡片强制设计规范 V2》的既定核心要求：单卡单决策、默认单卡、最多三项相关问题、标题/说明/选项数量约束、推荐依据和高级依据折叠、统一视觉系统、窄屏适配，以及科研讨论卡/参数决策卡/执行确认卡三类卡片。

本文件将其纳入 PFC Interaction 5.0 四规范体系，并补充与统一决策协议、模块工作流和执行授权的约束关系。若旧版文件中的其他细节与本 V2 正文不一致，应以本文件为本次四规范交付版本。
