# PFC Interaction 5.0.1 — 五份文件关系与使用说明

## 文件清单

1. `PFC_Interaction_5.0_技术报告_讨论深度强化修订版.md`：总技术报告，定义产品定位、架构、建设路线和总体验收。
2. `01_总体架构与科研工作流规范.md`：上位架构规范，定义六阶段、议题模型、科研档案和阶段回退。
3. `02_科研专业模块与技术能力规范.md`：定义 M1–M6 专业职责、技术深度、输入输出和跨模块协作。
4. `03_深度科研讨论与人机协作协议规范.md`：核心交互规范，定义多轮讨论、迭代深度、讨论模式、决策与长期记忆。
5. `04_提问卡片强制设计规范_V2.md`：结构化交互的强制 UI 规范。

## 约束关系

- 总技术报告负责解释完整方案和实施优先级。
- 01 是总体架构和科研工作流的规范依据。
- 02 是 M1–M6 专业职责的规范依据。
- 03 是讨论、迭代、协作、决策和科研连续性的规范依据。
- 04 是结构化卡片的唯一详细设计依据。

## 建议写入 SKILL.md 的强制约束

> 本 Skill 必须遵守 PFC Interaction 5.0.1 总技术报告及四份强制规范。对于复杂科研议题，必须执行多轮实质性讨论、方案比较、反方审查、用户反馈吸收、方案修订和验证规划。禁止以固定问题数量或少量问答自动完成研究阶段。必须维护课题级议题、假设、证据、决策和变更档案。Native Chat 承担复杂讨论；AUQ 仅承载已结构化的事项。任何模块、模板和卡片不得绕过上述规则。

## 冲突处理

- 总体阶段/资产/架构：以 01 为准。
- 专业模块职责与接口：以 02 为准。
- 讨论深度、迭代、通道、决策和授权：以 03 为准。
- 卡片结构、视觉和提交行为：以 04 为准。
- 总报告用于说明和实施规划；若其简述与规范细节不一致，以对应规范为准。

## 重要实现声明

这些文件是目标规范，不是实现完成证明。开发时必须建立“条款 → Skill 文件/模块 → 测试用例 → 实测证据”的追踪矩阵。对暂时无法实现的能力，必须记录降级行为和限制，不得静默删减规范要求。
