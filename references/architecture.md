# 架构：三方、两条通道、一个 Agent 中心

## 1. 结构

```
                 Human（操作者）
      研究目标 / 专业知识 / 判断 / 干预 / 授权
                       ⇅
              PFC Interaction
           Human  ↔  Agent 通道
       （Native Chat + AUQ 双通道并存）
                       ⇅
          ┌──────────────────────────┐
          │       Agent（中心）       │
          │ 理解 / 推理 / 翻译 / 汇报  │
          │ 讨论 / 协商 / 决策协调     │
          │ 计划 / 验证 / 结果反馈     │
          └──────────────────────────┘
                       ⇅
                  itasca-mcp
              Agent  ↔  PFC 通道
                       ⇅
                    Itasca PFC
     模型 / 参数 / 计算过程 / 状态 / 结果 / 异常
```

**关键约束**：PFC Interaction 与 itasca-mcp 之间**不直接通信**。两条通道通过 Agent 衔接。

## 2. 职责边界

| 主体 | 负责 | 不负责 |
|---|---|---|
| Itasca PFC | 真实数值仿真、维护模型状态、产生数据 | 向操作者解释科学意义 |
| itasca-mcp | 文档检索、Python/命令执行、任务管理、状态与 GUI 上下文返回 | 替 Agent 做科研判断；管理人机对话 |
| Agent | 读取证据、理解上下文、分析现象、提出建议、协调决策、调用工具、验证结果 | 把推测当成已验证事实；未经授权擅自决策 |
| PFC Interaction Skill | Human↔Agent 交互规范、通道路由、必要薄适配 | 直接连接/控制 PFC；重复任务管理；取代 Agent 推理 |
| Agent 宿主 UI / Native Chat | 连续对话、消息、原生交互呈现 | PFC 领域判断 |
| AUQ | 结构化问题队列、TUI/CLI 回答入口、异步响应获取 | 科研推理、PFC 状态读取、工作流编排 |

## 3. 版本与能力探测（重要）

上游工具会随版本变化。已核实本机 0.8.1 与公开 main 分支的文档工具命名和默认版本不同（见 `pr0/ITASCA_MCP_CAPABILITY_BASELINE.md`）。因此：

- **执行工具面**（execute_code / execute_task / check_task_status / interrupt_task / list_tasks）在两版本稳定，可作为 Skill 依赖面；
- **文档工具面**必须先探测实际工具名与参数，不得写死；
- 文档版本参数必须显式传入，不依赖默认值。

## 4. 事实、推断、建议必须分层

任何向操作者的输出，必须能回答"这个说法来自哪里"：

- **观测事实**：来自 PFC / itasca-mcp 的直接返回值、输出或图像（OBSERVED / VERIFIED）；
- **趋势判断**：多观测点或历史阶段的比较；
- **机理解释**：基于模型与岩石力学知识的解释，标注不确定性（INFERRED）；
- **备选方案**：可尝试的下一步实验操作；
- **待确认事项**：需要操作者判断或授权的内容。

INFERRED 不得伪装成 VERIFIED。

## 5. 第一版范围

**必须实现**：状态汇报规范、阶段识别与关键节点汇报、证据化表达、现象解释与不确定性标注、方向讨论、参数协商、决策结构化、操作前风险检查与确认、通过 itasca-mcp 执行、执行后状态验证与反馈、汇报频率与干预优先级规则、双通道路由、PFC2D/3D 典型流程验证。

**明确不做**：新 Bridge、PFC 状态采集/任务管理后端、复制 itasca-mcp 工具、独立 Agent 框架、强制 Web、PostgreSQL/Redis/消息队列、自建 AUQ 队列/TUI、Agent 退出后的自主分析、把建议当批准决策。
