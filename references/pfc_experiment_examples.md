# 典型协作示例：单轴压缩实验

用于 PR1/PR2 验收：验证 Agent 能否完成"状态读取—汇报—讨论—决策—执行—验证—反馈"闭环。

## 场景

研究目标：研究加载过程中的应力演化与裂纹发展，在峰值附近确定下一步实验策略。

## 标准协作流程

1. **提出目标**：操作者要求开展基准单轴压缩模拟。
2. **检查环境**：Agent 通过 itasca-mcp 检查模型、参数、Bridge 与运行环境（先探测工具名，显式传文档版本）。
3. **提交任务**：用 `execute_task` 提交建模与加载脚本，得到真实 task_id。
4. **过程监测**：用 `check_task_status` 获取进度；在 cycle 间隙用 `execute_code` 查询轴向应力、应变、不平衡力、裂纹数与分布。
5. **阶段汇报**：按 `status_report.md` 汇报当前阶段与关键变化，区分事实/判断/解释。
6. **提出建议**：给出"继续加载到峰值"或"提高峰值附近记录频率"等方案及风险。
7. **用户决策**：操作者决定先观察峰值附近裂纹演化再停止本轮。
8. **结构化**：Agent 复述决策为执行条件，检查当前脚本是否支持；必要时澄清。
9. **执行**：按 `decision_workflow.md` 检查风险与授权后，通过 itasca-mcp 调整任务或提交后续脚本。
10. **验证**：再次查询任务状态与模型数据，确认是否按预期执行。
11. **反馈与下一步**：汇报峰值、裂纹演化和任务结果，讨论下一组加载速率对比实验。

## 用户介入变体（Mode B）

- 用户在运行期间提出"降低加载速率"：Agent 判断是否已执行 → 查询模型状态 → 分析影响 → 复述确认 → 检查版本与状态 → 执行 → 验证；
- 用户提交新参数文件：文件变化 ≠ 文件已加载，必须先查询模型确认，再决定是否续跑；
- 用户拒绝建议并说明原因：Agent 不执行被拒方案，按理由重新制定方案并重新验证状态。

## 异常变体

- 任务失败或停滞：按 `anomaly_report.md` 汇报，列出已排查项与可能原因（标注推断），给出处理选项，用户决定后再行动；
- 状态未知：明确说"无法判断"，不用 unknown 冒充成功；恢复前重新核对状态。

## 验收要点

- 数值都有来源、单位、阶段；
- 不把推断写成事实，不把建议当批准；
- 用户回答确实改变了后续 PFC 执行并有状态证据；
- 高风险操作在执行前单独确认；
- GUI/Console、PFC2D/3D 的适用范围有明确测试记录（当前仅 PR0 静态核查完成）。
