# 汇报策略：事实分层、触发条件与表达模板

## 1. 五层表达结构

所有向操作者的状态汇报、解释和建议，按以下层次组织，让操作者能区分"事实"与"判断"：

| 层次 | 含义 | 来源 | 标注 |
|---|---|---|---|
| 观测事实 | 直接来自 PFC / itasca-mcp 的数值、输出、图像 | 工具返回值 | 注明单位、来源、实验阶段 |
| 趋势判断 | 多个观测点或阶段的比较 | Agent 分析 | 说明比较区间 |
| 机理解释 | 基于模型与岩石力学知识的解释 | Agent 推断 | 必须标注不确定性，不得冒充事实 |
| 备选方案 | 可尝试的下一步操作 | Agent 建议 | 说明预期收益与风险 |
| 待确认事项 | 需要操作者判断或授权的内容 | 协作需要 | 明确提出请求 |

示例：

> 观测：当前轴向应力仍在增长，最近一段加载裂纹数量明显增加（来源：`check_task_status`/`execute_code`，阶段：加载）。
> 判断：试样可能正从稳定损伤向加速损伤过渡。
> 建议：可继续加载并提高峰值附近记录频率，也可先暂停检查裂纹分布。
> 待确认：本轮优先获取峰值强度，还是优先捕捉峰后破坏过程？

## 2. 主动汇报触发条件（不是频繁打扰）

满足任一条件才汇报，不每 cycle / 每次工具调用都发消息：

1. 实验阶段切换（压密完成、开始加载、峰前、峰值、峰后）；
2. 预定义指标阈值或趋势条件（应力突变、裂纹加速、能量变化、接触状态变化）；
3. 异常或任务状态变化（失败、停滞、与预期不符）；
4. 关键实验结果出现；
5. 到达用户指定的检查点；
6. 下一步存在多个科学上有意义的选择；
7. 继续执行前必须获得用户决策或授权。

汇报频率控制模式：静默监测 / 关键节点汇报 / 异常立即汇报 / 定时摘要。由操作者指定或 Skill 按实验类型选择。

## 3. 数值与图表的硬约束

- 每个数值必须有来源、单位、对应实验阶段；不得凭空生成；
- 图表/图像必须来自真实模型数据或真实导出结果；
- Console 无头模式下 `plot` 命令是静默空操作，不产生文件：出图必须走离线 matplotlib 脚本或 GUI 导出（见 `itasca_mcp_boundary.md`）；
- 查询失败、超时或状态未知时，明确告知"未能获取"，不填假设值。

## 4. 简洁原则

- 汇报关键变化而非转储原始日志；避免反复注入大量数值造成上下文膨胀；
- 状态摘要优先用趋势与结论，原始细节由操作者按需索取；
- 长任务中记录已汇报事件，避免重复和遗漏。

## 5. 数据可信度分级与测量升级路径（E2E 实战补充）

产生数据 ≠ 数据可信。Agent 遇到以下信号时必须判定为"数据不可信"，不得据此下结论：

- 量级突变：应力从 1e7 骤降到 1e3；
- 峰值出现在加载最初几步（可能是边界重建瞬态，非材料峰值）；
- 单点测量剧烈跳动（相邻采样点差几个数量级）。

**逐级定位路径**（从测量到几何）：

1. 单点读数异常 → 改用多接触/多测点聚合；
2. 聚合仍异常 → 检查有效接触数（如 wall_contacts 是否只有个位数）；
3. 接触数过少 → 检查几何（试样外缘 vs 压板位置/尺寸是否匹配）；
4. 几何不匹配 → 把"修正测量/实验布置"作为决策项交给操作者，不自行挑一个数字继续。

**测量方法本身可以是协作对象**：当数据不可信时，Agent 应汇报"当前测量方法不足以回答这个问题"并请求操作者决定如何调整，而不是假装已有结论。

## 6. 能力边界声明

主动汇报只在"Agent 正在运行、可持续调用 MCP"时成立。不承诺：

- Agent 完全退出后后台自主通知；
- 没有工具调用时的实时事件推送（GUI 操作需主动拉取 `console_history`，bridge 广播仅为 doorbell）；
- GUI 事件能力在 Console 下等价存在。

向操作者说明限制时如实表述，不夸大能力。
