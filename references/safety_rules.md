# 安全规则与禁止行为

## 1. 绝对禁止

1. 虚构 PFC 状态、数值、图表、执行结果或任务 ID；
2. 把 Agent 的推测/建议写成已验证的 PFC 事实；
3. 把 Agent 的建议自动视为操作者已批准的实验决策；
4. 把用户模糊意图直接转换为高风险操作；
5. 绕过 itasca-mcp 自行实现 PFC 执行、状态采集或任务管理；
6. 让 AUQ 的回答绕过 Agent 直接触发 PFC 执行；
7. 用一个问题的回答去执行另一个实验/阶段的操作；
8. 执行失败或状态未知时报告成功。

## 2. 高风险操作清单（必须单独确认）

- 覆盖、删除、重命名已有模型/存档/结果文件；
- `model new`、`model restore`、`model reset` 等改变当前模型的动作；
- 不可逆的参数或接触模型变更；
- 长时间重算或大规模删除产物；
- 任何用户未明确授权、但会造成数据丢失或无法回退的操作。

确认必须绑定到**具体动作 + 参数 + 文件/对象**，不接受笼统的"同意所有"。

## 3. 数值与来源

- 关键数值注明来源工具、单位和实验阶段；
- 图表必须来自真实模型数据/导出结果；
- Console 无头模式 `plot` 命令静默空操作，不可作为出图依据；
- 无法获取数据时明确说明，不填假设值。

## 4. 通道与决策

- 同一待决事项只有一个有效交互实例；
- 超时不等于拒绝，断线不等于问题失效；
- 接受方案不等于授权执行；
- AUQ 回答只作为用户输入证据，需 Agent 结合当前状态解释验证。

## 5. 能力边界（不得夸大）

- 不宣称具备 GUI 实时事件推送：用户操作需主动拉取 `console_history`（0.6.17 实测），bridge 广播仅为 doorbell；
- 不把 GUI 事件能力外推到 Console：源码已确认 Console 模式不安装输入捕获器，用户直接键入的命令不可被观察，此能力为 unsupported；
- 不承诺 Agent 退出后的后台自主分析或通知；
- 不宣称任意位置暂停/恢复；阶段级检查点是第一版的真实能力；
- 不宣称已经通过真实 PFC 验收，除非有对应运行证据。

## 6. 版本诚实

- itasca-mcp 与 bridge 版本必须锁定；
- 工具名/参数以能力探测为准，不写死上游工具名；
- 未验证能力在文档中标注为"待验证"或"不支持"，不得写入已实现清单。
