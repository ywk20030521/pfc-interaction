# 主动协作与长任务运行策略

## 1. 目标模式

Agent 不等用户提问，而是在实验过程中主动判断何时汇报、何时邀请决策。但主动 ≠ 频繁打扰。

## 2. 主动行为清单

- **阶段汇报**：压密完成、开始加载、进入峰前、达到峰值、进入峰后；
- **异常汇报**：任务失败、计算停滞、指标异常、模型状态与预期不符；
- **关键变化汇报**：应力突变、裂纹增长加速、能量变化、接触状态变化；
- **决策邀请**：到达阶段分界点，需要操作者确定下一阶段目标；
- **建议讨论**：提出下一组实验、参数调整或结果验证建议。

## 3. 触发条件（满足才汇报）

1. 实验阶段切换；
2. 预定义指标阈值或趋势条件；
3. 异常或任务状态变化；
4. 关键实验结果出现；
5. 到达用户指定的检查点；
6. 下一步存在多个科学上有意义的选择；
7. 继续执行前必须获得决策或授权。

汇报频率模式：静默监测 / 关键节点汇报 / 异常立即汇报 / 定时摘要。具体策略由 Skill 结合宿主能力与用户偏好实现。

## 4. 长任务中的运行方式

- 用 `itasca_execute_task` 提交长任务，立即返回 task_id；
- 用 `itasca_check_task_status` 的 `wait_seconds` 等待，并周期性查询关键指标；
- 在 cycle 间隙用 `itasca_execute_code` 检查中间状态（共享 `__main__` 命名空间）；
- 到检查点时暂停推进，向用户汇报并等待决策；
- 记录已汇报事件，避免重复和遗漏。

**关键限制**：GUI 用户操作通过独立 `console_history` 端点主动拉取（0.6.17 实测；执行响应不再附加 `_context`），bridge 的 SSE 广播只是 doorbell，任务状态 SSE 主要用于客户端内部等待，均不构成独立实时推送。主动汇报要求 Agent 正在运行、有机会继续拉取。

## 5. 阶段级检查点（第一版的真实恢复能力）

1. 实验脚本预先定义可安全等待的检查点；
2. 到达检查点时保存阶段输入、参数版本、模型文件/状态证据和任务结果；
3. 当前阶段结束或进入已定义的安全等待状态；
4. 用户反馈到达后，重新检查 PFC 进程、Bridge、任务和模型状态；
5. 状态仍有效才恢复下一阶段；
6. 状态不一致 → 进入人工处理，不盲目续跑。

不承诺任意 Python 调用栈暂停/恢复；任务中断不等于暂停。

## 6. 能力边界声明

| 场景 | 是否支持 | 说明 |
|---|---|---|
| Agent 运行中，可持续调用 MCP | 支持 | 完整汇报—讨论—决策—执行闭环 |
| Agent 会话中断/重启 | 部分 | 用户需复述上下文；不承诺自动恢复记忆 |
| Agent 完全退出后后台通知 | 不支持 | 宿主无保证的定时/推送能力 |
| 用户长时间不回答 | 按超时/DEFER 处理 | 超时不等于拒绝；问题保留，不擅自执行 |

向用户如实说明当前所处场景与支持程度，不夸大。
